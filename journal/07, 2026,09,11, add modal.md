## What Broke

### The view switching would not work at first

The buttons looked right. The views were defined. But clicking did nothing.

Spent 45 minutes debugging. Turned out the `data-view` attributes on the buttons and the `id` attributes on the views were not matching.

Buttons had:

```html
<button data-view="dashboard">Dashboard</button>
```

Views had:

```html
<section id="view-dashboard">
```

The JavaScript was looking for `view-dashboard` when clicking `dashboard`. Should have worked. But one of the buttons had a typo in the `data-view` attribute. `analytics` had become `analyics`. Silent mismatch, no error. Just nothing happened.

**Diagnostic that found it:**

```js
console.log('Button clicked:', viewId);
```

One `console.log` and the typo was obvious.

### The status dots needed a color map

First draft used the same color for every dot. Wanted green for running, yellow for deploying, gray for planned, blue for docs.

Wrote a status class map:

```js
const statusClassMap = {
  running: 'status-running',
  deploying: 'status-deploying',
  planned: 'status-planned',
  docs: 'status-docs'
};
```

Then each dot's class is built from this map. Clean and extensible.

### The health bar

Wanted a horizontal strip showing node status at a glance. Ended up as four items in a flex container:

- Node 1, control plane, green
- Node 2, worker, green
- 256 GB HDD, yellow, 85 percent full
- k3s cluster, green, 2 of 2 nodes

These were mocked but the structure was real.

---

## Root Cause

Two things:

1. **Typos in data attributes are invisible.** No compile error, no warning. Just silent failure. `console.log` is the diagnostic.
2. **Mock data helps you design.** I did not have real node status yet. But mocking the values let me design the display. When real data came later, the display did not need to change.

---

## What I Learned

- **Always `console.log` the values your JS is reading.** Five seconds of logging saves an hour of guessing.
- **Mock data is not cheating.** It is prototyping. You design the shape of the data, then fill it in later.
- **A status indicator is just a colored dot plus a label.** Simple but incredibly effective for a dashboard.
- **Flexbox handles horizontal bars naturally.** The health bar is just `display: flex` with a gap. No positioning hacks needed.
- **Dark theme plus colored status dots looks professional by default.** No polish required.

---

## If This Happens Again

Debugging "nothing happens when I click":

1. Open DevTools, Console tab
2. Add `console.log('clicked', value)` at the top of the click handler
3. If nothing logs: the button is not wired up. Check the selector.
4. If it logs: the value is what you expect. Check the downstream logic.
5. If it logs the wrong value: typo in the HTML attribute.

Ninety percent of "nothing happens" bugs are selector mismatches or typos.
