# Entry 04: 2026,09,08 — First drive failure, OS corrupted, fresh flash

**Duration:** ~6 hours
**Outcome:** OS corrupted. Fresh DietPi flash. Drive kept, would fail again later.

---

## Context

Immich was installed bare metal on the t520. I wanted dedicated storage for it. A 500 GB 2.5 inch laptop HDD I had lying around.

This is the beginning of the drive saga that spans the next three weeks. **Drive A.**

---

## What I Tried

1. Connected the 500 GB drive to the t520
2. Formatted it, created the mount point
3. Added it to `/etc/fstab` so it would auto mount
4. Pointed Immich's data directories at the new drive
5. Rebooted to test

---

## What Broke

### Immediate instability

Within a few hours of Immich pointing at the new drive, the system became unstable:

- Random hangs
- SSH sessions timing out
- `dmesg` full of I/O errors
- Eventually, unbootable

### The drive errors

```
critical medium error, dev sdb, sector <varies> op 0x0:(READ)
I/O error, dev sdb, sector <varies>
EXT4-fs warning (device sdb1): htree_dirblock_to_tree: error -5
```

**Translation:**

- `critical medium error` means the physical disk is returning read errors
- `error -5` is `EIO`, Input/output error. The kernel cannot complete the I/O.
- `htree_dirblock_to_tree` means ext4's directory indexing is failing to read directory blocks

### OS corruption

The I/O errors eventually corrupted DietPi's own root filesystem. On reboot, the system dropped into emergency mode with a **read only filesystem**. The same pattern I would encounter again later. See Entry 15.

The OS could not boot properly. Time to start over.

---

## Root Cause

**Drive A was dying before I connected it.** Old 2.5 inch laptop drives are a lottery. Many are on their last legs. Adding it to the system and mounting it in fstab meant every boot would try to read and write to a failing disk.

When ext4 tries to write metadata to a bad sector, the filesystem becomes inconsistent. When the root filesystem encounters bad I/O, the kernel remounts read only to protect data, which breaks every service that needs to write.

**Second cause: bare metal Immich.** Because Immich was running natively, its write attempts went directly to the same failing drive. No isolation. When the drive had problems, everything suffered.

**What I should have done:** tested the drive before trusting it. Run `smartctl`, do a write test, check for errors.

---

## What I Learned

- **`dmesg | grep -iE 'error|fail|I/O'` is the first diagnostic for any random instability.** Most weird Linux behavior traces back to storage errors.
- **`critical medium error`** is hardware failure. Not fixable.
- **A failing drive can corrupt the OS.** If root writes to a bad sector, ext4 becomes inconsistent.
- **Bare metal means shared fate.** A failing drive breaks Pi-hole too, because it is on the same host.
- **Never trust a drive without testing it.** `smartctl`, a `dd` write test, or at minimum a few hours of use before committing.
- **Keep spares if you are working with old hardware.** You will need them.

---

## If This Happens Again

Storage corruption symptoms:

1. **Check kernel logs immediately:**
   ```bash
   sudo dmesg | grep -iE 'error|fail|I/O' | tail -30
   ```

2. **Test the drive:**
   ```bash
   sudo smartctl -a /dev/sdX
   ```
   If `Reallocated_Sector_Ct` or `Current_Pending_Sector` is greater than zero, the drive is failing.

3. **If the drive is bad:**
   - Remove it from `/etc/fstab`
   - Unmount it: `sudo umount /path/to/mount`
   - Stop services using it
   - **Do not try to fix the drive.** Replace it.
   - Consider a fresh OS install if the root filesystem was affected

4. **If the OS is corrupted:**
   - Boot from USB
   - Access the OS as a rescue environment
   - Remove bad fstab entries
   - If root is unrecoverable, reflash and start over

5. **Prevent recurrence:**
   - Only add drives to fstab after testing
   - Use `UUID=` not `/dev/sdX`, because device names shift
   - Add `nofail` to fstab options so the system will not fail to boot if the drive is missing:
     ```
     UUID=... /mnt/path ext4 defaults,nofail,noatime 0 2
     ```
